# يلا فون — Yalla Phone

تطبيق دردشة صوتية وألعاب بواجهة عربية RTL، سيرفر FastAPI، وقاعدة بيانات PostgreSQL.
الواجهة على المنفذ **3000** والـ API على المنفذ **8000**.

## التشغيل

```bash
docker compose -f docker-compose.yml up -d --build
```

- `web`: React + Vite مع إعادة تحميل حية.
- `api`: FastAPI + SQLAlchemy، ويطبّق مخطط قاعدة البيانات والبذور تلقائيًا عند الإقلاع.
- `db`: PostgreSQL 16.

## نظام الإعلانات والنشاطات والفعاليات

### واجهة المستخدم

- **الرئيسية `/`**: بانرات إعلانية متحركة (صورة/فيديو، تمرير تلقائي، مشاهدات ونقرات) + قسم
  «النشاطات والفعاليات» + متصدرون.
- **الفعاليات `/events`**: تصفية حسب النوع (يومية، أسبوعية، مسابقات، تحديات، مناسبات، حصرية).
- **تفاصيل الفعالية `/events/:id`**: الوسائط، الوصف، المواعيد، القواعد، الشروط، الجوائز، عدد
  المشاركين، زر المشاركة، ترتيب المتصدرين، والفائزون بعد الاعتماد.
- **مشاركاتي وجوائزي `/my-events`**: سجل المشاركات، الجوائز وحالتها، وكل حركة مالية.
- **المتصدرون `/leaderboard`**: ترتيب يومي/أسبوعي/كل الوقت.

### لوحة الإدارة `/admin/events`

- إنشاء/تعديل فعالية: النوع، اللعبة، الوصف، القواعد، الشروط، المواعيد، رسوم الدخول، عدد الفائزين.
- رفع صورة/فيديو أو إدخال رابط، وتحديد جوائز كل مركز (ذهب/عملات/ألماس/هدية/إطار).
- تفعيل/إيقاف المشاركة، نشر/إخفاء الفعالية، ونشر إعلان لها في الرئيسية بضغطة واحدة.
- إدارة الألعاب المتاحة (تفعيل/إيقاف، المدة، القواعد).
- إدارة البانرات مع إحصاء المشاهدات والنقرات.
- متابعة المشاركين والنتائج، احتساب الفائزين، اعتماد الجوائز، ثم إرسالها للحساب.

> **حماية اختيارية:** عند ضبط متغير البيئة `EVENTS_ADMIN_KEY` تصبح كل مسارات `/api/admin/*`
> مقفلة وتطلب الترويسة `X-Admin-Key`؛ تُدخل القيمة من صفحة الإدارة. بدون ضبطه تبقى اللوحة
> مفتوحة مثل بقية لوحة التحكم الحالية (التطبيق بلا نظام حسابات متعدد).

### الألعاب

`lucky_challenge` (تحدي الحظ)، `prize_wheel` (عجلة الجوائز)، `mystery_box` (صندوق المفاجآت)،
`points_challenge` (جمع النقاط)، `quiz` (مسابقة أسئلة)، `group_game` (تحدي الفرق).

كل النتائج تُحسب على الخادم:

- رمي النرد/العجلة/الصناديق عشوائية من `secrets` في السيرفر.
- أسئلة المسابقة تُرسل بدون مفتاح الإجابة، وتُقيَّم الإجابات مقابل نسخة محفوظة على الخادم.
- مشاركة واحدة لكل حساب في كل فعالية (قيد فريد في قاعدة البيانات).
- رسوم الدخول تُخصم داخل معاملة مع قفل صف الرصيد.
- الجوائز تُصرف مرة واحدة فقط عبر مرجع فريد في `event_ledger`، وإعادة الإرسال لا تضاعف الرصيد.
- كل مشاركة/فوز/صرف له سجل قابل للتدقيق.

### التحديث اللحظي

قناة WebSocket: `/api/ws/events`. الواجهة تشترك فيها وتحدّث البانرات والفعاليات والمتصدرين
ولوحة النتائج لحظيًا عند أي تغيير.

### رفع الوسائط

`POST /api/admin/uploads` (صور/فيديو حتى 30MB) يحفظ الملف في `backend/uploads/` (مستثنى من git)
ويخدمه على `/api/uploads/<file>`. يمكن أيضًا استخدام رابط خارجي مباشرة.

### الإشعارات

- **تعمل الآن:** إشعارات داخل التطبيق عند بدء الفعالية، عند الفوز، وقبل النهاية بـ30 دقيقة،
  إضافة إلى إشعارات المشاركة والصرف.
- **Push الحقيقي على الهاتف يحتاج مفاتيح FCM** من Firebase (لا توجد مفاتيح في هذا المستودع)،
  لذلك لا تُرسل إشعارات نظام Android/iOS حاليًا.

### محتوى البداية

عند أول إقلاع تُنشأ 6 فعاليات افتتاحية و3 بانرات وكتالوج الألعاب، مرة واحدة فقط. يمكن للأدمن
تعديلها أو حذفها بالكامل من `/admin/events`. لا تُنشأ حسابات وهمية ولا نتائج مزيفة.
