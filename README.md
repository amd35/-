# TON Voice — تطبيق اجتماعي للدردشة الصوتية والألعاب

منصة اجتماعية كاملة: **واجهة ويب** للتجربة الفعلية، **لوحة إدارة** مستقلة، **خادم FastAPI**، و**قاعدة بيانات PostgreSQL**.
كل شيء يعمل من مصدر المستودع نفسه عبر `docker compose`، والبيانات تُحفظ على الخادم لا في التطبيق.

> هذا ملف حقيقي وقابل للتشغيل — لكنه **ليس المشروع كاملاً** كما ورد في المواصفات. القسم
> [«ما تم تنفيذه وما لم يُنفّذ بعد»](#ما-تم-تنفيذه-وما-لم-يُنفّذ-بعد) يوضح بدقة ما يعمل فعلياً
> وما يحتاج حسابات خارجية أو تطبيق Android.

---

## المكوّنات

| المكوّن | المسار | المنفذ | الوصف |
| --- | --- | --- | --- |
| موقع الويب | `web/` | 3000 | React + Vite، عربي RTL، أربعة أقسام: الرئيسية والمتجر، الألعاب، الغرف الصوتية، الأصدقاء |
| لوحة الإدارة | `admin/` | 3001 | React + Vite، لوحة منفصلة، صلاحياتها مُنفّذة على الخادم |
| الخادم | `backend/` | 8000 | FastAPI + SQLAlchemy + WebSocket + Alembic (وثائق الـ API على `/docs`) |
| قاعدة البيانات | `db` | 5432 | PostgreSQL 16 |

واجهة الويب تتحدث مع الخادم من نفس الأصل عبر وكيل خادم التطوير (`/api`, `/media`, `/ws`)، لذلك لا توجد مشاكل CORS أو ملفات تعريف ارتباط بين مواقع مختلفة.

## البنية

```
web/  ──┐                         ┌── PostgreSQL (users, rooms, wallets, ledger, gifts, orders …)
admin/ ─┼── /api (REST)  ── FastAPI ──┤
        └── /ws  (WebSocket)         └── مبدّل إشارات WebRTC (offer / answer / ICE) بين أعضاء الغرفة
```

- **الأصوات الحقيقية:** كل غرفة تستخدم `RTCPeerConnection` بين المتحدثين (mesh)، والإشارات تمر عبر الـ WebSocket الخاص بالتطبيق. لا توجد أصوات مسجلة ولا أزرار شكلية.
- **الأرصدة:** كل حركة تمر من `backend/app/economy.py` داخل معاملة واحدة مع قفل صف المحفظة (`SELECT … FOR UPDATE`) ومرجع فريد لكل حركة، فلا يمكن خصم قيمة الهدية مرتين ولو تكرر الطلب.
- **الصلاحيات:** تُتحقق على الخادم في كل مسار (`get_admin_user` + خريطة صلاحيات لكل دور)، وإخفاء الأزرار في الواجهة ليس حماية.

## التشغيل

### داخل بيئة Base44 (المستخدمة هنا)

التهيئة تعيش خارج المستودع في ملف بيئة Base44:

```bash
docker compose --project-name app --project-directory "$BASE44_PROJECT_ROOT" \
  -f "$BASE44_CONFIG_ROOT/docker-compose.base44.yml" up -d
```

الخِدَم: `db` → `migrate` (ترحيلات Alembic + بيانات أولية) → `api` → `web` و`admin`.

### خارج البيئة (سيرفر خاص)

```bash
cp backend/.env.example backend/.env      # املأ القيم بنفسك
docker compose -f docker-compose.example.yml up -d --build
```

`docker-compose.example.yml` نموذج للأسرار والإعدادات ونشر حقيقي (بدون وضع التطوير).

## البيانات الأولية والترحيلات

```bash
# داخل حاوية api أو backend
alembic upgrade head          # إنشاء/تحديث المخطط
python -m app.seed            # بيانات أولية (هدايا، باقات، إعدادات، غرفة نموذجية، حساب الإدارة)
python -m app.cli create-admin --username ops --email ops@example.com
python -m app.cli reset-password --username ops
```

- المخطط في `backend/app/models.py` والترحيل في `backend/alembic/versions/`.
- `AUTO_CREATE_TABLES=1` تنشئ الجداول عند الإقلاع للتطوير السريع؛ في النشر استخدم Alembic.
- **كلمة مرور الإدارة:** حساب الإدارة الأول يُنشأ من `ADMIN_USERNAME` و`ADMIN_PASSWORD`. بعد تغيير `ADMIN_PASSWORD` في صفحة الأسرار وإعادة تشغيل الخدمة يتم تحديث كلمة المرور تلقائياً. هذا الحساب للحماية الأولية فقط؛ في الإنتاج أنشئ حسابات إدارة بالدور المناسب من `app.cli` أو من اللوحة.

## الاختبارات

```bash
docker compose … exec -T api sh -ec "cd /workspace/backend && python -m pytest -q"
```

تُنشئ مجموعة الاختبارات قاعدة `app_test` منفصلة تلقائياً وتغطي:

- التسجيل/الدخول/الملف الشخصي/رفع الصورة (وتقييد الصيغة والحجم).
- الغرف: الانضمام، المقاعد، رفع اليد والموافقة، الكتم، الطرد، الحظر، غرفة بكلمة مرور.
- الهدايا: رصيد غير كافٍ، الخصم، حصة المستلم، **منع الخصم المكرر**، ورفض الطلب بلا مفتاح فريد.
- التحويلات والذرية، طلبات الشحن **لا تُضاف إلا بتأكيد**، مزود الدفع غير المُعدّ يرفض (503)، السحب معطّل/مفعّل ورفض الطلب يُعيد الرصيد.
- صلاحيات الإدارة على الخادم (403 للمستخدم العادي)، تعديل الرصيد مع سجل تدقيق، تعديل الأسعار وسجل التدقيق.
- WebSocket: الحضور، الدردشة، تسليم إشارات WebRTC، ورفض انضمام غير الأعضاء.

## الخدمات الخارجية المطلوبة

| الخدمة | الغرض | الحالة | التكلفة / الملاحظات |
| --- | --- | --- | --- |
| **Stripe** | شراء الكوين/الذهب | المفاتيح غير مُعدّة → كل طلب شحن يبقى «معلّقاً» | ~2.9% + 0.30$ لكل عملية. **لا يدعم الدينار العراقي**، لذلك يُعرض السعر بالدينار ويُحصّل بالدولار وفق سعر الصرف في لوحة الإدارة |
| **خادم TURN** (coturn أو مزود) | إتمام الاتصال الصوتي بين شبكات مختلفة | غير مُعدّ | coturn على VPS صغير ~5$ شهرياً، أو مزود مُدار مثل Metered/Twilio. بدون TURN يعمل الصوت داخل نفس الشبكة فقط |
| **SMTP** (بريد) | رموز التحقق واستعادة كلمة المرور | غير مُعدّ → الرمز يُسجّل في سجل الخادم | مجاني عبر مزود مثل Brevo/Resend بحدود شهرية، أو مدفوع |
| **بوابة SMS** | التحقق برقم الهاتف | غير مُعدّة | مدفوعة (Twilio ~0.05$ للرسالة) — يمكن الاعتماد على البريد حالياً |
| **FCM** (Firebase) | إشعارات فورية على الأجهزة | غير مُعدّ | مجاني؛ يحتاج مشروع Firebase وملف الخدمة |
| **استضافة الخادم** | تشغيل API + Postgres + TURN | محلياً عبر compose | VPS من 10–20$ شهرياً + شهادة HTTPS (Let's Encrypt مجاناً) |
| **Android build** | إصدار APK | غير مُضمَّن في هذه المرحلة | يحتاج Android SDK وJDK؛ مجاني |

## ما تم تنفيذه وما لم يُنفّذ بعد

**يعمل فعلياً (مُختبر):**

1. حسابات حقيقية: تسجيل بالبريد/الهاتف، دخول/خروج، رموز تحقق واستعادة كلمة مرور، ملف شخصي وصورة ووصف، حالة متصل/غير متصل، مستويات ونقاط خبرة وشارات.
2. الغرف الصوتية: إنشاء (اسم، وصف، صورة، خلفية، عدد مقاعد، خصوصية وكلمة مرور، هدايا، دردشة)، انضمام/خروج، مقاعد مقفلة، رفع اليد والموافقة/الرفض، تشغيل/إيقاف المايك، كتم وطرد وحظر، تعيين مشرفين ومساعدين، نقل الملكية، دردشة مباشرة، تغيير الخلفية، عدّاد الأعضاء اللحظي.
3. الصوت الحقيقي عبر **WebRTC** مع مبدّل إشارات على الخادم.
4. الهدايا: 12 هدية (عادية/مميزة/فاخرة)، إرسال لمستخدم أو غرفة، خصم من المرسل وإضافة حصة المستلم، سجل كامل، منع التكرار، تفعيل/تعطيل لكل غرفة.
5. المحفظة: كوين وذهب منفصلان، سجل عمليات كامل، تحويل بين المستخدمين، منع تعديل الرصيد من التطبيق.
6. المتجر: باقات كوين وذهب، عروض وإعلانات داخلية، أسعار بالدينار والدولار، سجل مشتريات وحالة كل طلب، عضوية VIP (تُفعّل بعد تأكيد الخادم فقط).
7. طلبات الشحن والسحب: إنشاء الطلب، مراجعة الإدارة، قبول/رفض مع إرجاع الرصيد عند الرفض، وربط مزود الدفع عبر webhook موقّع.
8. الأصدقاء: بحث بالاسم/المعرّف، طلبات صداقة، حظر، محادثات خاصة، إشعارات داخل التطبيق مع تفضيلات لكل نوع.
9. لوحة الإدارة: إحصائيات، المستخدمون والأرصدة والحالات والأدوار، الغرف، الهدايا وأسعارها، المتجر والباقات، الشحن والسحب، الإعدادات وسعر الصرف، الإعلانات والبث الجماعي، البلاغات وسجل التدقيق.

**لم يُنفّذ بعد (بصراحة):**

- **تطبيق Flutter/APK:** لم يُبنَ في هذه المرحلة. لا يوجد Android SDK في بيئة العمل، ولا يمكن اختباره على جهاز حقيقي من هنا.
- **الألعاب (لودو ودومينو):** الصفحة موجودة وتقول صراحةً إنها قيد التنفيذ — لا أزرار وهمية.
- **إشعارات الأجهزة (FCM):** الإشعارات داخل التطبيق تعمل، والإشعارات الفورية تحتاج مشروع Firebase.
- **الدفع الإلكتروني والسحب النقدي:** الكود جاهز والمفاتيح غير مُعدّة، ولا يُضاف أي رصيد قبل تأكيد مزود الدفع. لا يوجد أي دفع وهمي.
- **مؤثرات الصوت (صوت روبوتي):** تحتاج معالجة صوت على الجهاز (AudioWorklet) — المرحلة القادمة.
- **التحقق الفعلي للصوت بين جهازين:** يحتاج جهازين فعليين وشبكتين + TURN.

## ملاحظات أمنية

- HTTPS على الواجهة العامة، وكلمات المرور بـ bcrypt، والرموز بـ JWT قصيرة/طويلة الأجل حسب الإعداد.
- كل عملية حساسة تُتحقق من صلاحيتها على الخادم، مع تحديد معدل الطلبات (`RATE_LIMIT_DISABLED=1` للاختبارات فقط).
- الأرصدة محمية من التكرار بمرجع فريد لكل حركة، وكل تعديل إداري يُسجّل في `audit_logs`.
- المفاتيح لا تدخل المستودع: تأتي من `/run/base44/app.env` (أو متغيرات البيئة في النشر الخاص).
- في الإنتاج: استخدم ملفات تعريف ارتباط آمنة (httpOnly) بدلاً من `localStorage`، وفعّل نسخاً احتياطياً دورياً لقاعدة البيانات (`pg_dump`)، وحدّد معدل الطلبات عبر Redis لأن الحد الحالي في العملية الواحدة.
- الإبلاغ والحظر والإشراف على المحتوى موجودة (بلاغات + كتم/طرد/حظر + سجل تدقيق).

## ملاحظات WebRTC

- كل متحدث يفتح اتصالاً مستقلاً بكل متحدث آخر (mesh). مناسب حتى ~10 متحدثين؛ الغرف الكبيرة تحتاج SFU (LiveKit أو Janus أو مزود مُدار).
- بدون TURN سيفشل الصوت بين شبكتين مختلفتين (بيانات الهاتف مقابل الواي فاي مثلاً).
- المتصفح يحتاج إذناً صريحاً للمايك، والتطبيق يطلب الإذن فقط عند الضغط على تشغيل المايك.
- على الأجهزة المحمولة يجب أن يبقى التطبيق في المقدمة للصوت المستمر؛ هذا أحد الأسباب التي تجعل تطبيق Flutter ضرورياً للاستخدام الفعلي.

## تعليمات بناء APK (عند إضافة تطبيق Flutter)

```bash
# بعد إضافة مجلد mobile/ (المرحلة القادمة)
cd mobile
flutter pub get
flutter build apk --release --dart-define=API_BASE_URL=https://api.example.com
# الناتج: build/app/outputs/flutter-apk/app-release.apk
```

يحتاج البناء: Flutter SDK 3.x، Android SDK 34، JDK 17، وتوقيع الإصدار بمفتاحك (`key.properties`).
