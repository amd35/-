# يلا لوهان (Yalla Lohan) — منصة اجتماعية (صوت + ألعاب + هدايا)

منصة متكاملة: **Backend حقيقي (FastAPI + PostgreSQL)**، **موقع ويب للتجربة**، **لوحة إدارة مستقلة**،
و**تطبيق Flutter للأندرويد** يبنى إلى APK. كل الأرصدة والحركات والألعاب تُتحقق على الخادم،
ولا توجد أزرار شكلية: ما تراه في الواجهة يقابله تنفيذ فعلي في الـ API وقاعدة البيانات.

> **حالة الصدق (مهم):** القسم `الصدق والتغطية` في نهاية هذا الملف يذكر صراحة ما لم يُنفَّذ
> أو لم يُختبر بعد — بما في ذلك خدمات خارجية تحتاج حسابات ومفاتيح حقيقية.

## 1. البنية

| المكوّن | التقنية | المنفذ |
| --- | --- | --- |
| الواجهة الخلفية | FastAPI + SQLAlchemy 2 + Alembic | 8000 |
| قاعدة البيانات | PostgreSQL 16 | 5432 (داخلي) |
| موقع الويب (تطبيق المستخدم) | React + Vite (RTL عربي) | **3000** |
| لوحة الإدارة | React + Vite (مستقلة) | 3001 |
| تطبيق الأندرويد | Flutter + flutter_webrtc | APK |

```
backend/    FastAPI: حسابات، غرف صوتية، هدايا، محفظة، متجر، ألعاب، إدارة، WebSocket
web/        واجهة المستخدم (5 أقسام: الرئيسية · المتجر (زينة النرد) · الألعاب · الغرف الصوتية · الأصدقاء)
admin/      لوحة الإدارة المستقلة (صلاحيات على الخادم، ليست إخفاء أزرار)
flutter_app/ تطبيق الأندرويد
```

### الاتصال الصوتي (Voice)
- **WebRTC حقيقي** (شبكة mesh بين المشاركين) + **خادم إشارات على WebSocket** داخل الـ Backend.
- خوادم ICE تأتي من `/api/meta/public`: STUN عام افتراضيًا، و TURN يُضاف تلقائيًا بإحدى طريقتين:
  خادم coturn خاص (`TURN_URL` / `TURN_USERNAME` / `TURN_CREDENTIAL`)، أو خدمة Cloudflare TURN
  المجانية بلا خادم (`CLOUDFLARE_TURN_KEY_ID` / `CLOUDFLARE_TURN_API_TOKEN`) حيث يولّد
  `backend/app/rtc.py` مفاتيح مؤقتة لكل عميل ويخزّنها حتى قرب انتهائها، وعند أي فشل من المزوّد
  يبقى STUN فقط ولا يتأثر `/api/meta/public`.
- صلاحية المايك تُفرض على الخادم: مقعد + عدم كتم الإدارة (لا يوجد رفع يد ولا موافقة).
- إشارات الصوت (SDP/ICE) لا تُمرَّر إلا بين أعضاء نفس الغرفة الصوتية.



### الغرف الصوتية (القواعد الفعلية)
- **غرفة واحدة لكل مستخدم**: قيد جزئي فريد في قاعدة البيانات (`uq_room_owner_open` على الغرف
  المفتوحة) + تحقق على الخادم. الغرفة تبقى لصاحبها حتى يحذفها (`DELETE /api/rooms/{id}`).
- **منصة بـ 12 مقعداً** (`ROOM_SEATS` في `app/room_service.py`، وعدد المقاعد ثابت على الخادم).
- **الانضمام مباشر**: من يدخل الغرفة يصبح عضواً ومستمعاً بلا رفع يد ولا موافقة، والصعود إلى أي
  مقعد فارغ مباشر. المايك مكتوم افتراضياً عند الصعود، والكتم يعني عدم إرسال أي صوت إطلاقاً.
- **مؤشر الكلام**: يُقاس مستوى الصوت الحقيقي (AnalyserNode) لحلقة حول صورة من يتحدث فعلاً.
- **إعجاب الغرفة**: `POST /api/rooms/{id}/like` — صف واحد لكل مستخدم (قيد فريد `uq_room_like`).
- **عقوبات الطرد**: ساعتان أو 12 شهراً (`app/room_service.BAN_DURATIONS`) بتوقيت الخادم، مع
  `expires_at` في `room_bans` ورفع تلقائي بعد انتهاء المدة، وقائمة محظورين للمالك مع إلغاء يدوي.
- **الصلاحيات**: المالك (إدارة كاملة، تعيين مشرفين، منح صلاحية الطرد، حذف الغرفة) · المشرف
  (كتم/إنزال/طرد وفق ما يمنحه المالك عبر `can_ban`) · العضو (انضمام، صعود، مايك، إعجاب).
  لا يستطيع المشرف طرد المالك أو تجاوز صلاحياته (تحقق على الخادم).

### الألعاب (لودو ودومينو)
- محرّكات قواعد نقية على الخادم: `backend/app/games/ludo.py` و `backend/app/games/domino.py`.
- النرد والقطع تُدار **على الخادم** (لا يمكن للعميل اختيار أرقامه)، وكل نقلة تُتحقق قبل تطبيقها،
  وتُسجَّل في جدول `game_moves` (سجل قابل للمراجعة + إعادة الاتصال).
- لودو: 4 قطع لكل لاعب، 6 تُخرج القطعة، ثلاث ستات تُفقد الدور، أكل القطع ما عدا المربعات الآمنة،
  والوصول إلى البيت يحتاج رقمًا دقيقًا. دومينو (6-6): أعلى دبل يبدأ، السحب من المخزن،
  الدور المبتَل يتوقف، والفائز يجمع نقاط أيدي الآخرين حتى هدف قابل للتعديل من لوحة الإدارة.
- **لا يوجد أي مراهنة أو مال حقيقي في الألعاب** (المكافأة ماس من النظام فقط).

## 2. التشغيل

### داخل Base44 (بيئة التطوير)
```bash
docker compose -f docker-compose.base44.yml up -d --build
# الويب: http://localhost:3000 · لوحة الإدارة: http://localhost:3001 · الـ API: http://localhost:8000/docs
```
`docker-compose.base44.yml` يشغّل الكود من المستودع مباشرة (bind mount) مع إعادة تحميل تلقائية،
ويعتمد على `.env.base44-defaults` (قيم مؤقتة آمنة ومُلتزَم بها) ثم `/run/base44/app.env`
(أسرار المنصة) — وملف المنصة هو الذي يفوز دائمًا.

### تشغيل محلي عادي
```bash
cp backend/.env.example backend/.env      # عدّل القيم
docker compose -f docker-compose.base44.yml up -d --build
```

### الترحيلات والبذور
- الترحيلات: خدمة `migrate` تشغّل `alembic upgrade head` تلقائيًا قبل تشغيل الـ API.
- يدويًا: `docker compose -f docker-compose.base44.yml run --rm api alembic upgrade head`
- البيانات الأولية (`AUTO_SEED=1`): الهدايا، باقات المتجر، الإعدادات، حساب الإدارة، وغرفة نموذجية.
  حساب الإدارة = `ADMIN_USERNAME` (افتراضيًا `admin`) وكلمة المرور من `ADMIN_PASSWORD`.

### الاختبارات
```bash
docker compose -f docker-compose.base44.yml exec -T api python -m pytest -q
```
تغطية الاختبارات الحالية: الحسابات والأمان، الغرف والمقاعد والمايك، الهدايا والمحفظة والعملات
الذرية ومنع التكرار، المتجر وطلبات الشحن/السحب، الأصدقاء والرسائل، المتابعة (علاقة أحادية
الاتجاه بلا تكرار — `tests/test_follows.py`)، **وقواعد لودو ودومينو كاملة**
(محرّك + مسار HTTP كامل + منع اللعب خارج الدور + مكافأة الفوز مرة واحدة).

## 3. بناء APK من المصدر

```bash
cd flutter_app
tool/android_setup.sh https://api.your-domain.com    # يولّد android/ ويضيف الصلاحيات و minSdk 24
flutter pub get
flutter build apk --release --dart-define=API_BASE_URL=https://api.your-domain.com
# الناتج: build/app/outputs/flutter-apk/app-release.apk
```
- استخدم HTTPS في الإنتاج (سكربت الإعداد يسمح بـ HTTP للمحلي فقط).
- للتوقيع للنشر: أنشئ `keystore` واضبط `android/key.properties` ثم
  `flutter build apk --release --split-per-abi`.
- المحاكي المحلي يستعمل `--dart-define=API_BASE_URL=http://10.0.2.2:8000`.

## 4. النشر (خادم حقيقي)

1. **API**: صورة إنتاج (بدون bind mount) + `uvicorn --workers N` خلف Nginx/Proxy مع شهادة TLS.
   اضبط متغيرات البيئة من `backend/.env.example`، ونفّذ `alembic upgrade head` قبل الإقلاع.
2. **قاعدة البيانات**: PostgreSQL مُدارة + نسخ احتياطي يومي (`pg_dump`) واختبار استعادة دوري.
3. **الويب ولوحة الإدارة**: `npm run build` ثم تقديم مخرجات `dist/` عبر Nginx،
   وتمرير `/api` و`/ws` إلى الـ API (نفس الأصل لتجنب مشاكل الجلسة و WebSocket).
4. **TURN**: إمّا خادم coturn خاص وإمّا مفاتيح Cloudflare TURN (انظر قسم الأسرار) — لضمان الصوت
   بين شبكات الجوال المختلفة.
5. **HTTPS إلزامي** في الإنتاج: الكوكيز والـ WebSocket والتطبيق تعتمد عليه.

## 5. الأسرار والخدمات الخارجية (تحتاج حسابات حقيقية)

| الخدمة | المتغيرات | مطلوبة للإقلاع؟ | التكلفة التقديرية |
| --- | --- | --- | --- |
| مفتاح توقيع الجلسات | `SECRET_KEY` | نعم | — |
| كلمة مرور حساب الإدارة | `ADMIN_PASSWORD` | نعم | — |
| Stripe (دفع بالبطاقة) | `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET` | لا | عمولة لكل عملية (~2.9% + 0.30$) — **Stripe لا يدعم IQD**: الأسعار تُعرض بالدينار وتُحسب بالدولار حسب سعر الصرف في الإعدادات |
| SMTP (رموز التحقق والاستعادة) | `SMTP_HOST`, `SMTP_USER`, `SMTP_PASSWORD` | لا | مجاني/مدفوع حسب المزود |
| TURN — خادم coturn خاص | `TURN_URL`, `TURN_USERNAME`, `TURN_CREDENTIAL` | لا | VPS صغير ~5$ شهريًا |
| TURN — خدمة Cloudflare | `CLOUDFLARE_TURN_KEY_ID`, `CLOUDFLARE_TURN_API_TOKEN` | لا | مجاني (بلا خادم، بمفاتيح مؤقتة) |
| إشعارات فورية على الجهاز (FCM) | غير مهيأة | لا | مجاني |

**تشغيل TURN عبر Cloudflare (مجاني وبلا خادم):** أنشئ TURN key من
[لوحة Cloudflare Calls](https://dash.cloudflare.com/?to=/:account/calls)، ثم اضبط
`CLOUDFLARE_TURN_KEY_ID` (معرّف المفتاح) و`CLOUDFLARE_TURN_API_TOKEN` (الرمز السري) في أسرار المنصة.
الخادم يولّد مفاتيح مؤقتة (افتراضيًا 24 ساعة، تُضبط بـ `TURN_CREDENTIAL_TTL`) ويوزّعها على الويب
وتطبيق Flutter معًا عبر `/api/meta/public` — دون أي تعديل في الواجهات. المفتاح الطويل العمر يبقى
على الخادم ولا يوصل للعميل أبدًا.

**بدون هذه المفاتيح**: التطبيق يعمل، لكن (أ) رمز التحقق ورمز الاستعادة يُكتبان في سجل الـ API
بدل إرسال بريد، (ب) لا يُضاف رصيد تلقائيًا عند الشحن (يبقى الطلب `pending` ويمكن للإدارة
اعتماده يدويًا)، (ج) الصوت يعمل على نفس الشبكة عبر STUN فقط.

> لا تضع أي مفتاح حقيقي في المستودع: الأسرار تُدار من لوحة المنصة (تُوصل عبر `/run/base44/app.env`).
> الأسماء والوصف موجودة في `/.base44/environment.json`.

## 6. الأمان

- كلمات المرور بـ **bcrypt**، والجلسات بـ **JWT** قابلة للانتهاء.
- **كل** عملية إدارية تمر عبر `get_admin_user` + صلاحية دور على الخادم (`ROLE_PERMISSIONS`)
  ويُسجَّل كل إجراء مهم في `audit_logs` (من فعل ماذا ومتى).
- عمليات الأرصدة ذرية (`SELECT ... FOR UPDATE`) مع **`ref` فريد لكل حركة** و**مفتاح منع تكرار**
  (`idempotency_key`) للهدايا والشحن والسحب → لا خصم مزدوج عند تكرار الطلب.
- المستخدم لا يستطيع تعديل رصيده من التطبيق: لا يوجد أي مسار يكتب في المحفظة مباشرة.
- تحديد معدل الطلبات على تسجيل الدخول والتسجيل وإنشاء الطاولات وحركات اللعب.
- التحقق من المدخلات عبر Pydantic، وأسماء الملفات المرفوعة مقيّدة، والحجم محدود (`MAX_UPLOAD_MB`).
- التقارير والحظر والكتم: `reports` + إجراءات إدارية مسجّلة.
- **لم يُنفَّذ بعد**: تخزين أسرار المستفيدين في السحب بتشفير إضافي، و Redis لتشارك حدود المعدل
  بين عدة عمليات (حاليًا لكل عملية حد مستقل).

## 7. الصدق والتغطية (ما لم يُنفَّذ أو لم يُختبر)

**نُفِّذ واختُبر فعليًا في هذه البيئة**
- كل اختبارات الـ Backend تنجح: `53 passed` (تشمل غرفة واحدة لكل مستخدم، الانضمام المباشر،
  12 مقعداً وامتلاءها، المايك، الإعجاب، عقوبات الطرد ساعتين/12 شهراً وانتهاءها التلقائي،
  ومفاتيح TURN المؤقتة: توليدها مرة واحدة، تخزينها مؤقتًا، والتراجع إلى STUN عند فشل المزوّد).
- الويب ولوحة الإدارة يعملان من المصدر على المنفذين 3000 و3001، والـ API يعمل ويتصل بقاعدة البيانات.

**نُفِّذ لكن لم يُختبر آليًا (يحتاج جهازك)**
- **APK**: كود Flutter مكتوب وكامل للأقسام الأساسية (تسجيل، غرف صوتية مع WebRTC، لودو، دومينو،
  أصدقاء، محفظة ومتجر)، لكن **لم يُبنَ APK داخل بيئة التطوير هذه** (لا يوجد Android SDK هنا).
  البناء على جهازك بالأمر في القسم 3.
- **الاتصال الصوتي بين جهازين**: يحتاج مايك حقيقي ومتصلين — لا يمكن التحقق منه في بيئة بلا صوت.
- **مؤثرات تغيير الصوت (صوت روبوتي)**: **لم تُنفَّذ**. تحتاج معالجة صوت أصلية (native) على
  الأندرويد (flutter_webrtc لا يوفرها)، وتحتاج اختبارًا على أجهزة حقيقية قبل إعلانها.
- **الإشعارات الفورية على الجهاز (Push/FCM)**: الإشعارات داخل التطبيق تعمل عبر WebSocket،
  أما إشعارات النظام فهي غير مهيأة (تحتاج مشروع Firebase ومفاتيحه).

**يحتاج إعدادًا خارجيًا (غير مُفعَّل الآن)**
- **الشحن الإلكتروني**: كود إنشاء الطلبات واستقبال إشعار مزود الدفع موجود، لكن لا رصيد يُضاف
  دون `STRIPE_SECRET_KEY` + `STRIPE_WEBHOOK_SECRET` حقيقيين ومُختبَرين. أي طلب الآن يبقى
  `pending` ويُعتمد يدويًا من لوحة الإدارة.
- **السحب النقدي**: النظام مبني ومحمي (`withdrawal_enabled=false` افتراضيًا) ويُفتح من لوحة
  الإدارة بعد ربط وسيلة دفع قانونية والتحقق منها.
- **البريد**: بدون SMTP يبقى رمز التحقق في سجل الخادم.

## 8. واجهات API

- التوثيق التفاعلي: `/docs` و`/redoc` (OpenAPI كامل).
- أهم المجموعات: `/api/auth`, `/api/users`, `/api/rooms`, `/api/gifts`, `/api/wallet`,
  `/api/store`, `/api/friends`, `/api/follows`, `/api/notifications`, `/api/reports`, `/api/games`, `/api/admin`.
- سجل اللعب: `GET /api/games/rooms/{id}/moves` · هندسة لوحة لودو: `GET /api/games/board/ludo`.
- WebSocket واحد: `/ws?token=...` — رسائل الغرف والدردشة وإشارات WebRTC وحركات الألعاب والإشعارات.
